Final Plan: Multi-block files + networking + HTTP get/put (v0.2.0)
Milestone A — FS: multi-block (chained) files
Add node_next (word per node, 0xFFFF=end) to the in-memory table and the per-volume on-disk layout (content shifts +1 sector).
Version-aware format: superblock version 3 = chained layout; old version-2 volumes load/read fine (single-block), new features need a fresh fmt — no data loss on upgrade.
Chained content nodes get a new node_type (e.g. 3) so they're invisible to find_child/path walk but skipped by the allocator.
New helpers fs_file_len, fs_read_file, fs_write_extend (append a node to a chain); route existing view/show/lookfor/find/edit/owrite/del through them. Delete frees whole chains.
Cap: ~64 nodes/volume → files up to ~10 KB/volume (fine for text/config; note in README).
Test: big-file round-trip via get, then view/sync/reboot and verify.
Milestone B — NIC + base stack (netinfo / bounce / monitor / dns / net)
As planned: RTL8139 bring-up (PCI 10EC:8139, BAR0, polled RX/TX), Ethernet II + ARP + IPv4 checksum + ICMP echo + UDP + DNS client, same-subnet/gateway routing, static IP config (10.0.2.15/gw 10.0.2.2/dns 10.0.2.3), resb DMA buffers.
Test: netinfo, dns google.com, bounce 10.0.2.2, bounce 8.8.8.8, bounce google.com, monitor google.com (line per reply, Esc stops), unroutable → clean timeout. No-NIC regression.
Milestone C — Minimal TCP engine
Polled, no IRQs: 3-way handshake (SYN→SYN-ACK→ACK), seq/ack tracking, send/recv with a small advertised window, HTTP/1.0 + Connection: close so body = read-until-FIN (no chunked encoding).
Retransmit-on-no-ACK with a 1s-granularity RTO tick (RTC-based) — bounded, Esc-cancelable.
Test: raw TCP exchange against a host service via QEMU hostfwd.
Milestone D — HTTP get / put
URL parsing (http://host[:port]/path), DNS for hostname, connect, request build, response header parse.
get <url> <file> — streams body into a new multi-block file (via Milestone A writer), sync.
put <url> <file> — POST body = file content with Content-Length.
Test (QEMU): run a plain HTTP server on the host (e.g. Python http.server + a tiny POST endpoint), forward with -netdev user,id=n0,hostfwd=tcp::8080-:80; get http://10.0.2.2:80/... <file> and put a file back, verify contents. Also get of a >160 B file to prove chaining.
Budget & build
Bump KERNEL_SECTORS 260 → 290 (boot.asm:27) — the combined ~20-22 KB of new code won't otherwise fit. Still well below FS_LBA_START=300, and the 2 MB image has room.
NIC/DNS/TCP/HTTP buffers all resb (no file bytes); RX ring 8 KB, TCP recv ~2-4 KB, HTTP/tx scratch.
NASM flat-binary build unchanged; verify kernel.bin ≤ 290 sectors each milestone.
Honest risk notes
TCP is the hard part — minimal-but-correct retransmission/timing under polling. QEMU slirp terminates the guest's TCP (it ACKs the guest and relays), which is forgiving; real-hardware LAN servers are less so. Each milestone keeps it testable.
No TLS — plain HTTP only. On real hardware you'll point get/put at your own plain-HTTP server on the LAN. HTTPS sites (most public ones) won't work — that's a fundamental limit without a crypto stack.
RTL8139 is legacy; for modern real hardware a GbE driver (RTL8169/e1000e) remains a later milestone. [RESOLVED - see status update at top: e1000 and RTL8168 drivers both shipped alongside RTL8139.]
